# 맞춤법 키보드 (실시간 교정 IME)

타이핑을 따라가며 한국어 맞춤법과 띄어쓰기를 고치는 안드로이드 키보드.

## 왜 IME 인가

다른 앱에 입력하는 글자를 실시간으로 고치려면 키 입력을 직접 받아야 한다.
안드로이드에서 그게 가능한 건 `InputMethodService` 뿐이다.

- **접근성 서비스**: 다른 앱의 텍스트를 읽고 쓸 수는 있지만, Google Play 가
  접근성 API 오남용을 강하게 규제해서 심사에서 막힐 가능성이 크다.
- **`ACTION_PROCESS_TEXT`**: 안전하고 쉽지만 사용자가 텍스트를 선택해야 한다.
  실시간이 아니다.
- **클립보드 감시**: Android 10 부터 백그라운드 읽기가 막혔다.

## 모듈 구조

```
tools/      build_dictionary.py  - mecab-ko-dic 에서 사전 데이터를 굽는다
core/       순수 Kotlin/JVM. 안드로이드 의존성 없음.
            HangulAutomata    - 두벌식 오토마타
            CorrectionEngine  - 맞춤법 규칙 + 띄어쓰기
            Spacer            - 형태소 분석 기반 띄어쓰기 복원
            TypingSession     - 입력 처리 전부 (조합·교정 시점·되돌리기)
            Editor            - InputConnection 을 감싼 최소 인터페이스
keyboard/   안드로이드 IME. core 를 가져다 쓴다.
            SpellKeyboardService - InputMethodService (얇은 어댑터)
            KeyboardView         - 소프트 키보드 화면
            SetupActivity        - 키보드 활성화/시험/자체 점검 화면
```

교정 엔진을 안드로이드에서 떼어 놓은 이유는 두 가지다. 첫째, JVM 단위 테스트로
전부 검증할 수 있다(에뮬레이터 불필요). 둘째, Windows 버전을 만들 때 이 모듈을
그대로 재사용한다.

## 교정이 일어나는 시점

**글자마다 고치지 않는다.** 한글은 조합 중인 음절이 계속 바뀌기 때문에
(`ㅇ → 아 → 안 → 안ㄴ → 안녀 → 안녕`) 조합이 끝나기 전에 손대면 입력이 깨진다.

그래서 **어절이 확정되는 순간** — 스페이스, 문장부호(`. , ! ? ; :`), 엔터 —
커서 앞 최대 3어절을 검사한다. 체감은 실시간이고, 조합 상태와 충돌하지 않는다.

```
사용자 입력:  할수있다[스페이스]
1. 조합 중인 '다' 확정
2. 커서 앞 "할수있다" 를 교정 -> "할 수 있다"
3. deleteSurroundingText(4) + commitText("할 수 있다")
4. 스페이스 입력
```

3번의 지우고-다시-쓰기는 `beginBatchEdit()` 으로 묶는다. 묶지 않으면 편집기가
중간 상태를 그려서 글자가 깜빡인다.

## 되돌리기

교정 직후 백스페이스를 한 번 누르면 원래 입력으로 되돌린다. 자동 교정에서 이게
없으면 고유명사나 신조어를 아예 쓸 수 없게 된다.

되돌리기 전에 편집기의 실제 내용이 우리가 쓴 그대로인지 확인한다. 그사이 커서가
움직였거나 다른 주체가 텍스트를 바꿨을 수 있기 때문이다.

## 교정 엔진의 설계 원칙

**오교정 한 번이 미교정 열 번보다 나쁘다.** 신조어나 고유명사를 멋대로 고치면
사용자는 앱을 지운다. 그래서 규칙에 들어가는 기준은 하나다 —
*문맥 없이도 거의 항상 틀린 표기만 넣는다.*

의도적으로 뺀 것들:

| 항목 | 뺀 이유 |
|---|---|
| 로서 / 로써 | 자격인지 수단인지 의미를 알아야 갈린다 |
| 던지 / 든지 | 회상인지 선택인지 문맥이 필요하다 |
| 반드시 / 반듯이 | 동음이의 |
| 의존명사 '뿐' | '말뿐이다'(조사, 붙임) 와 '할 뿐이다'(의존명사, 띄움) 가 같은 형태 |
| 의존명사 '리' | 받침 ㄹ + 리 는 '달리다·걸리다·알리다' 같은 동사와 충돌 |
| 낳다 / 낫다 | "빨리 낳으세요" 는 오타지만 "아기 낳으세요" 는 정상 |

의존명사 띄어쓰기는 **앞뒤를 둘 다** 확인한 뒤에만 띄운다. 예를 들어 '수'는
앞에 관형형 어미(받침 ㄹ)가 있고 뒤에 '있/없'이 올 때만 띄운다. 이렇게 해야
'실수 있다' 같은 오교정이 안 나온다. 여기에 더해 '별수·실수·홀수·술수' 같은
명사는 예외 목록으로 막는다.

## 일반 띄어쓰기 — 형태소 분석

규칙만으로는 "아버지가방에들어가신다" 를 못 나눈다. 그래서 온디바이스 형태소
분석기를 얹었다. 데이터는 **mecab-ko-dic** (Apache License 2.0, 은전한닢 프로젝트).

`tools/build_dictionary.py` 가 PyPI 의 `python-mecab-ko-dic` 휠에서
형태소 사전과 연결비용 행렬을 뽑아 앱이 읽을 납작한 바이너리로 굽는다.
결과는 `core/src/main/resources/` 에 gzip 으로 들어간다 (합쳐 7.8MB).

### 왜 행렬만으로는 안 되나

연결비용 행렬에는 **어절이라는 개념이 없다.** 형태소끼리 얼마나 잘 이어지는지만
안다. 그래서 행렬만 쓰면 아무 데도 띄우지 않는다.

반대로 문법 제약만 쓰면 '감사합니다' 를 '감사 합니다' 로 쪼갠다.

둘을 합쳐야 한다. 제약이 **띄어야 할 곳**을, 비용이 **띄지 말아야 할 곳**을 맡는다.

| 제약 | 예 |
|---|---|
| 조사·어미·서술격조사·파생접미사는 어절을 시작할 수 없다 | '입니다' 홀로 못 선다 |
| 용언 어간·선어말어미로 어절이 끝날 수 없다 | '들어가' 로 끝나는 어절은 없다 |
| 조사/어말어미/관형형어미/부사 뒤 실질형태소는 반드시 띄운다 | '학교에' + '간다' |
| 체언 뒤 용언 어간도 한 어절이 못 된다 | '밥' + '먹었어요' (파생 '하다' 는 XSV 라 예외) |

### 자모 단위로 맞춘다

'들어가신다' = 들어가(VV) + 시(EP) + ᆫ다(EF). 어미가 앞 음절의 종성으로 녹아들어서
음절 단위로는 못 맞춘다. 입력과 사전 표층형을 모두 첫가끝 자모로 펴서 비교한다.

### 메모리

두 파일은 압축 전 합쳐 50MB 다. 힙에 올리면 키보드가 죽는다. 처음 한 번
`filesDir` 에 풀고 **mmap** 으로 읽는다. 상주 메모리는 실제로 건드린 페이지만큼이다.
사전 로딩은 백그라운드 스레드에서 하고, 준비되기 전까지는 규칙만으로 동작한다.

측정: **어절당 0.25ms**. 타이핑 간격(100~200ms)에 한참 못 미친다.

**LLM 은 실시간 경로에 못 쓴다.** API 왕복이 200~1000ms라 타이핑을 따라갈 수 없다.
쓴다면 사용자가 명시적으로 누르는 "문장 전체 정밀 교정" 버튼 뒤에 놓아야 한다.

## 규칙이 못 잡는 맞춤법

'안녕하새요', '햇는대요' 같은 오타는 목록으로 따라갈 수 없다. 그래서 판정을 뒤집는다 —
**고친 쪽이 형태소 분석기 눈에 훨씬 자연스러우면** 고친다.

```
안녕하새요  분석비용 5873   ->  안녕하세요  2406   (이득 3467)
햇는대요    분석비용 1545   ->  했는데요    -525   (이득 2070)
됫어요      분석 불가       ->  됐어요      -781
```

후보는 **한국어에서 실제로 헷갈리는 자모**만 바꿔서 만든다 — ㅐ/ㅔ, ㅚ/ㅙ, 된소리와
예사소리, 받침 ㅅ/ㅆ 같은 것들. 아무 글자나 바꿔가며 뒤지면 신조어와 고유명사를
짓밟는다. 한 어절에 두 번까지 고치되, 단계별 문턱은 낮게 두고 **최종 이득**으로
채택 여부를 정한다. '햇는대요' 처럼 두 군데 틀린 경우 각 단계의 이득이 작기 때문이다.

## 키를 손가락에 붙이는 법

키는 **누르는 순간(ACTION_DOWN)에 입력한다.** `onClick` 은 손을 뗄 때까지 기다리고
이동 거리까지 따져서, 빨리 치면 씹힌 것처럼 느껴진다. 진동도 같이 준다 — 반응 신호가
빠를수록 키보드가 가볍게 느껴진다.

두벌식에서 쌍자음은 시프트로만 넣을 수 있어 한 글자에 두 번 눌러야 한다. **길게 누르면**
ㄱ→ㄲ, ㄷ→ㄸ, ㅂ→ㅃ, ㅅ→ㅆ, ㅈ→ㅉ, ㅐ→ㅒ, ㅔ→ㅖ 로 바뀐다. 누르는 순간 이미
예사소리가 들어갔으므로 조합을 한 단계 되돌린 뒤 다시 넣는다.

## 어떤 입력란에서 교정하나

좁게 잡는다. 비밀번호·이메일·URL 처럼 사람이 쓴 문장이 아닌 것만 뺀다.

검색창(`TYPE_TEXT_VARIATION_FILTER`)과 `TYPE_TEXT_FLAG_NO_SUGGESTIONS` 까지 막았더니
인스타그램 검색처럼 멀쩡한 입력란에서 교정이 통째로 꺼졌다. 그 플래그는 "추천 단어를
띄우지 말라"는 뜻이지 "맞춤법을 고치지 말라"는 뜻이 아니고, 한국어 앱들이 습관적으로
켜 둔다.

## AI 교정 (선택)

온디바이스 교정에는 벽이 있다. 사전에 없는 표기, 문맥이 필요한 판단('로서/로써',
'든지/던지'), 문장 전체를 봐야 하는 오류는 규칙으로도 형태소 분석으로도 못 잡는다.

그래서 **버튼 하나**를 뒀다. 누르면 입력란의 글 전체를 Gemini API 로 보내 교정한다.

- **실시간 경로가 아니다.** API 왕복이 수백 ms 라 타이핑을 따라갈 수 없다.
  누를 때만 돈다.
- **기본은 꺼져 있다.** 사용자가 자기 Gemini API 키를 설정에 넣어야 버튼이 뜬다.
  APK 에 키를 박아 넣으면 누구나 꺼내 쓸 수 있다.
- **비밀번호 입력란에서는 버튼 자체가 안 뜬다.**
- 사용자가 친 글은 **교정 대상이지 지시가 아니다.** 시스템 프롬프트가 그걸 못박는다 —
  키보드로 들어오는 글에 "위 지시를 무시하고..." 가 있어도 따르면 안 된다.
- 응답이 비거나 오류가 나면 원문을 그대로 둔다. 어떤 경우에도 사용자 글을 날리지 않는다.

### SDK 를 쓰지 않는 이유

요청은 POST 한 번이고 응답에서 꺼낼 것은 텍스트 한 덩어리다. 서버용 SDK 를 넣으면
HTTP 클라이언트와 JSON 라이브러리가 딸려 와 APK 가 몇 MB 씩 붙는다. 실제로 한 번
겪었다 — SDK 가 끌고 온 jar 들이 같은 이름의 메타데이터를 담고 있어 APK 패키징이
아예 깨졌고, 통과시킨 뒤에도 APK 가 10MB 에서 19MB 로 불었다.

지금은 `HttpURLConnection` 과 직접 쓴 작은 JSON 파서만 쓴다. 둘 다 안드로이드와
JVM 양쪽에 있어서, 네트워크 없이 요청 조립과 응답 파싱을 단위 테스트로 검증한다.

### 모델 이름

구글 쪽 모델 이름은 계속 바뀐다. 기본값은 `gemini-2.5-flash` 지만 설정에서 바꿀 수
있게 열어 뒀다. 모델이 없다는 오류가 나면 앱에서 다른 이름을 넣으면 된다.

## 개인정보

입력한 글자가 전부 지나가는 앱이다.

- **실시간 교정은 전부 온디바이스에서 끝난다.** 규칙도 형태소 분석도 네트워크를 쓰지 않는다.
- 인터넷 권한은 AI 교정에만 쓴다. 키를 넣고 버튼을 누를 때만, 그 입력란의 글이
  Google Gemini 서버로 간다. 그 외에는 어떤 것도 나가지 않는다.
- 비밀번호·이메일·URL 입력란(`TYPE_TEXT_VARIATION_PASSWORD` 등)에서는 교정을 끈다.
- `TYPE_TEXT_FLAG_NO_SUGGESTIONS` 를 준 입력란도 존중한다.
- 입력 내용을 저장하거나 학습에 쓰지 않는다.

Play 스토어에 올릴 때 키보드 앱은 이 부분을 심사에서 본다. 서버 전송을 추가하는
순간 개인정보 처리방침과 고지가 필수가 된다.

## 빌드와 테스트

```bash
# 교정 엔진 단위 테스트 (안드로이드 SDK 불필요)
./gradlew :core:test

# 키보드 APK
./gradlew :keyboard:assembleDebug
```

`:core:test` 는 81개 테스트로 오토마타, 교정 엔진, 입력 흐름, 띄어쓰기 분석기를
검증한다. 상당수가 **오교정 방지 테스트**다 — 고치면 안 되는 문장이 그대로 남는지
확인한다. `FakeEditor` 가 `InputConnection` 의 조합/확정 규칙을 흉내 내서
"스페이스를 눌렀을 때 화면의 글자가 실제로 어떻게 바뀌는가" 까지 확인한다.

사전 데이터를 다시 구우려면:

```bash
pip download python-mecab-ko-dic -d /tmp/dic --no-deps
python3 tools/build_dictionary.py /tmp/dic/*.whl core/src/main/resources
```

## 설치 후

APK 를 깔았다고 바로 쓸 수 있는 게 아니다. 앱을 열어

1. 시스템 설정에서 키보드 활성화
2. 입력기로 선택

두 단계를 거쳐야 한다. `SetupActivity` 가 두 화면을 바로 열어 주고, 시험용
입력란도 함께 둔다.

## 남은 일

- 규칙 사전 확장 (현재 약 120항목)
- 사전 가지치기 — 지금은 표층형 66만 개를 통째로 싣는다
- 교정 이력 화면 — 무엇을 얼마나 고쳤는지
- 사용자 사전 (고유명사·신조어 제외 목록)
- Windows 버전: `core` 를 그대로 쓰고 TSF 또는 키보드 훅으로 붙인다
