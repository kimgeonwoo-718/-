# 계정과 구독 공유 (설계)

안드로이드·아이폰·윈도우가 **구독 하나를 같이 쓰게** 하려고 만든다.
이 문서는 세 세션이 다 읽는다 — 서버는 안드로이드 세션이, 윈도우 쪽 소비는 윈도우 세션이 맡는다.

## 왜 필요한가

구독은 지금 **구글 플레이 구매 토큰** 하나로 돌아간다. 폰을 바꿔도 같은 구글 계정이면
Play 가 복원해 주니 안드로이드 안에서는 문제가 없다.

문제는 밖이다.

| | 스토어 | 구매 토큰을 얻을 길 |
|---|---|---|
| 안드로이드 | Google Play | 있다 |
| 아이폰 | App Store | **다른 스토어다.** Play 구매를 모른다 |
| 윈도우 | **없다** | 아예 없다 |

윈도우에는 스토어가 없어서 "이 사람이 구독자인가" 를 물어볼 데가 없다. 그래서 계정이 필요하다.

## 구조 — 계정은 구매를 가리키는 포인터다

**구독 상태의 진실은 여전히 Play 다.** 계정은 "누가 어떤 구매를 샀나" 만 기억한다.

    계정 ──가리킴──> 구매 토큰 ──확인──> Google Play (또는 App Store)

이렇게 두는 이유:

- **환불·해지·만료를 우리가 따로 관리하지 않는다.** Play 가 아니라고 하면 아니다.
- 하루 한도는 지금처럼 **구매 토큰 해시**로 센다. "결제 하나에 한도 하나" 가 그대로 산다.
- 계정 표가 날아가도 안드로이드는 멀쩡하다 — 거긴 Play 에 직접 묻는다.

### 흐름

**안드로이드 (구매하는 곳)**

1. Play 로 결제 → 앱이 구매 토큰을 받는다 (지금 그대로)
2. 사용자가 설정에서 로그인
3. 앱이 서버에 `{신원 증명, 구매 토큰}` 을 보낸다 → 서버가 계정에 구매를 붙인다

**윈도우·아이폰 (쓰기만 하는 곳)**

1. 사용자가 로그인
2. 서버가 그 계정에 붙은 구매 토큰을 찾아 Play 에 확인
3. 구독 중이면 AI 기능이 열린다

## 신원 증명 — 구글 로그인으로 정했다 (2026-09-22)

앱이 구글 로그인으로 ID 토큰을 받아 서버에 준다. 서버가 **구글 공개키로 서명을 확인**하고
`sub`(구글 계정마다 붙는 바뀌지 않는 번호)를 해시해 계정 열쇠로 쓴다.

**이메일·이름은 저장하지 않는다.** 토큰 안에 들어 있어도 읽지 않는다 — 키보드 앱이 사람
이름을 모아 둘 이유가 없고, 모으지 않으면 샐 것도 없다.

고려했다 버린 쪽은 **연결 코드**(안드로이드가 여섯 자리를 띄우고 다른 기기가 입력)다.
개인정보가 0 이고 윈도우 쪽이 훨씬 쉽지만, **안드로이드를 영영 버리면 복구가 막힌다** —
코드를 새로 뽑을 데가 없어진다. 돈 내는 기능이라 그 구멍을 두기 어려웠다.

### 그래서 따라오는 숙제

- **Play 정책**: 계정을 만드는 앱은 앱 안 계정 삭제 + 웹에서 삭제를 요청할 주소를 둬야 한다.
  아직 안 만들었다. 출시 전에 필요하다.
- **아이폰**: 구글 로그인을 넣으면 **애플 로그인도 같이** 넣어야 한다(App Store 규정).
- **윈도우**: 데스크톱에는 구글 SDK 가 없다. OAuth 기기 코드 흐름이나 브라우저를 띄워
  되돌려받는 길을 윈도우 세션이 짜야 한다. 서버는 ID 토큰만 받으면 되므로 서버 일은 없다.

## 서버 (만들었다)

    accounts (id, google_sub_hash, purchase_token, store, created_at, updated_at)
    devices  (token_hash, account_id, label, created_at, seen_at)

`google_sub_hash` 와 `purchase_token` 둘 다 유일 색인이다 — 구글 계정 하나에 우리 계정
하나, 구매 하나에 계정 하나.

| 길 | 누가 | 보내는 것 | 받는 것 |
|---|---|---|---|
| `POST /v1/account/signin` | 모든 기기 | `{idToken, purchaseToken?, label?}` | `{deviceToken, plan}` |
| `POST /v1/account/signout` | 기기 | `X-Device-Token` | `{ok}` |
| `POST /v1/account/subscription` | 윈도우·아이폰 | `X-Device-Token` | `{plan}` |
| `POST .../generateContent` | 모든 기기 | `X-Purchase-Token` **또는** `X-Device-Token` | 교정문 |

안드로이드는 구매 토큰을 같이 보낸다 → 그 구매가 계정에 붙는다.
윈도우·아이폰은 로그인만 한다 → 이미 붙어 있는 구매를 찾아 쓴다.

### 지킨 것

- **기기 토큰은 해시로만 저장한다.** 발급할 때 한 번 내주고 우리는 해시만 갖는다.
  데이터베이스가 새도 그것만으로 남의 기기 행세를 할 수 없어야 한다.
- **구매 토큰은 절대 안 내보낸다.** 그 자체가 구독 증명이라, 윈도우에 내려보내면 그게
  새는 통로가 된다. 확인 결과만 돌려준다. 시험이 몸통과 헤더를 뒤져 본다.
- **`aud` 를 반드시 본다.** 이게 없으면 **남의 앱에 발급된 멀쩡한 구글 토큰으로도** 우리
  계정에 들어온다. `GOOGLE_CLIENT_IDS` 가 비어 있으면 로그인을 아예 안 받는다.
- **한도는 저절로 지켜진다.** 기기 토큰이 계정을 거쳐 같은 구매로 풀리므로 폰에서 쓰든
  윈도우에서 쓰든 "결제 하나에 한도 하나" 다. 시험이 그걸 못 박는다.
- **기기는 다섯 대까지.** 로그인 하나로 여럿이 나눠 쓰는 것을 막는다.

### 설정해야 할 것

`GOOGLE_CLIENT_IDS` — 우리 OAuth 클라이언트 ID 들을 쉼표로. 안드로이드·아이폰·윈도우가
저마다 다르다. **안 적어 두면 로그인이 503 으로 막힌다**(열어 두느니 닫는 쪽).

## 안드로이드 (만들었다)

설정 → 교정 칸 맨 아래에 **로그인 행**이 있다. `AccountManager` 가 Credential Manager 로
계정 고르는 창을 띄워 ID 토큰을 받고, 구매 토큰이 이 폰에 있으면 **같이 보낸다** —
그래야 이 폰이 산 구독이 계정에 붙어 윈도우·아이폰이 찾아 쓸 수 있다. 받은 기기 토큰은
`Prefs.deviceToken` 에 두고, 교정 요청마다 `X-Device-Token` 으로 같이 실린다.

- 옛 `GoogleSignIn` API 말고 **Credential Manager** 를 쓴다. 그쪽은 접혔다.
- **빌드에 클라이언트 ID 가 없으면 행이 통째로 숨는다.** 눌러 봐야 오류만 난다.
  `GOOGLE_CLIENT_ID`(환경 변수 또는 `gradle.properties` 의 `googleClientId`) → `BuildConfig`.
  CI(`build-apk.yml`)에 값이 적혀 있다. 저장소 변수 `GOOGLE_CLIENT_ID` 가 있으면 그것이 우선이다.
- **로그아웃은 서버가 뭐라 하든 폰에서 지운다.** 망이 끊겼다고 로그인 상태로 남아 있으면
  다시 누를 길이 없다.
- **nonce 를 안 쓴다.** 서버가 기억할 데가 없어서다. ID 토큰은 수명이 한 시간이고 `aud`·
  서명·만료를 다 보므로 지금은 이것으로 둔다.

## 구글 클라우드 쪽 (2026-09-23 만들었다)

사용자 본인 계정의 "스펠 키보드" 프로젝트에 클라이언트 둘을 만들었다. Play 개발자 계정과
명의가 달라도 상관없다 — 클라이언트는 "패키지 + 서명 지문" 에 묶이고, 서버는 ID 문자열만 본다.

| 종류 | 무엇에 쓰나 | 어디에 적었나 |
|---|---|---|
| 웹 | ID 토큰의 `aud`. 서버가 이것을 확인한다 | `server/wrangler.toml` `GOOGLE_CLIENT_IDS`, `build-apk.yml` `GOOGLE_CLIENT_ID` |
| Android | 폰에 계정 창이 뜨게 한다. 값을 어디에도 적지 않는다 | 콘솔에만 (`com.spellkeyboard.ko` + SHA-1) |

**둘이 짝이 맞아야 한다** — 앱에 넣은 웹 클라이언트 ID 가 서버 목록에 없으면 401 이다.
안드로이드 Credential Manager 가 `aud` 에 넣는 것은 **웹 클라이언트 ID** 다.

SHA-1 은 CI 로그 "서명 지문" 단계에 찍힌다. 지금 CI 서명 키: `22:41:99:15:…:5A:3E`.
**Play 에 올리면 Play 가 자기 키로 다시 서명한다** — 그때 Play Console → 앱 무결성의
앱 서명 키 SHA-1 로 Android 클라이언트를 하나 더 만들어야 스토어 설치본에서 로그인된다.

동의 화면은 **테스트 중** 상태다. 테스트 사용자로 등록한 계정만 로그인된다. 출시할 때
"프로덕션으로 푸시" — 기본 항목(이메일·프로필)만 쓰니 구글 심사는 없다.

## 남은 것

- **Play 서명 키 SHA-1 로 Android 클라이언트 추가** — 스토어에 올릴 때.
- **동의 화면을 프로덕션으로** — 출시할 때.
- **계정 삭제** — Play 정책이 요구한다. 앱 안 + 웹 주소.
- **윈도우 쪽**(윈도우 세션 일): 구글 로그인으로 ID 토큰을 받아 `/v1/account/signin` 에
  보내고, 받은 `deviceToken` 을 저장해 교정 요청마다 `X-Device-Token` 으로 싣는다.
  **설치 ID 를 커밋하지 마라** — 공개 저장소다.
- **기기 토큰이 안 늙는다.** 지금은 한 번 받으면 계속 산다. 기기를 잃었을 때 빼는 길이
  `signout` 뿐이라, 나중에 "내 기기 목록" 을 만들면 거기서 뺄 수 있어야 한다.
